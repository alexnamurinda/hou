# Hotspot Operators Union

A simple union website for hotspot operators and community connectivity stakeholders.

## HOU member accounts

The member portal stores accounts in the `HOU` MySQL database. Create the database itself in your hosting console, then configure the portal's database connection. On the first portal visit, it automatically creates the `members`, `auth_attempts`, `member_announcements`, `member_announcement_reads`, `member_profiles`, and `member_payments` tables if they do not exist. Announcement image and PDF attachment columns are added automatically to existing databases. Administrators can create, edit, publish, and delete member updates in `admin/updates.php`; published updates appear in the member portal's Updates section. The Updates menu badge counts published posts each member has not opened; opening a post with Read more marks it as read. Uploaded update images are stored under `images/updates` (maximum 5 MB; JPEG, PNG, or WebP). Optional PDF attachments (maximum 5 MB) are stored in the database and served only to signed-in members for published updates. The PHP web-server user needs permission to create and write files in the image directory, and the database user needs permission to create and alter tables in `HOU`. [`database/HOU.sql`](database/HOU.sql) is also available for manual setup. The local XAMPP setup uses `127.0.0.1`, database user `root`, and an empty password; production defaults to the restricted `hou_user` account.

The admin member directory stores its password hash and one-time setup-code hash in a protected JSON file outside the website directory, so admin setup and sign-in do not require MySQL. On Linux, the default file is `/var/lib/hou/admin-credentials.json`; set `HOU_ADMIN_CREDENTIALS_FILE` in the PHP server environment to use another path. For first-time setup on a Droplet, create the protected directory for the PHP-FPM account (commonly `www-data`) with `sudo install -d -o www-data -g www-data -m 700 /var/lib/hou`, then run `sudo -u www-data php /var/www/HOU/admin/create-setup-token.php` over SSH. Enter the printed one-time code at `/admin/setup.php` with a strong password of at least 12 characters. The code expires after 30 minutes and is invalidated once used. Administrators sign in at `/admin/login.php`; member details and document previews still require the member database. Admin sign-in and setup attempts are rate-limited in the protected file.

Registration is a three-step process: collect the member's name, phone, and email; verify the email with a short-lived one-time code; then create a password. After successful registration, a unique HOU registration number is emailed to the member. It is eight characters in the format `AA12345B` (two uppercase letters, five digits, and one uppercase letter), is also available in the member portal, and can be used to log in instead of a phone number. Keep it safe; the membership certificate will be provided in the members portal. Existing member records are assigned a registration number automatically when the portal next connects to the database.

OTP and registration-number email are sent through Brevo's HTTPS API, so the production PHP installation must include the cURL extension. Configure `HOU_BREVO_API_KEY` in the PHP server environment using a protected secret; never commit the API key to this repository. The verified sender is `info@hotspotoperators.org`.

### Namecheap email setup

Choose either Namecheap Private Email or the email service included with your cPanel hosting; Namecheap does not allow both services to be active for the same domain at once. Create the `info@hotspotoperators.org` mailbox with the selected service. If the domain uses Namecheap DNS, open **Domain List → Manage → Advanced DNS → Mail Settings** and select **Private Email** for Private Email hosting. If the domain uses external nameservers, make equivalent DNS changes at the active DNS provider. Add or verify the MX and SPF records shown by the email service, then publish the DKIM record supplied in its dashboard. Do not create a second SPF record if one already exists; merge the authorized senders into one SPF value.

Namecheap Private Email may continue to be used for receiving mail, while Brevo handles OTP delivery. Authenticate `hotspotoperators.org` in Brevo, verify `info@hotspotoperators.org` as a sender, and configure the Brevo API key only in the PHP server environment. Allow DNS time to propagate and test delivery before enabling registration.

For any other environment, configure `HOU_DB_HOST`, `HOU_DB_PORT`, `HOU_DB_NAME`, `HOU_DB_USER`, and `HOU_DB_PASSWORD` in the PHP server environment (for PHP-FPM, in its pool configuration, then restart PHP-FPM). Do not put database or SMTP passwords in this repository. Use a database account restricted to the `HOU` database, with permission to create tables and alter the member profile table during initial setup. Registration and login use the PHP session cookie; newly registered members are signed in and taken directly to the member portal. The portal opens on a profile-completion overview. Members can save their Address, Business, Network, and Citizenship details one step at a time; completing Citizenship returns them to Overview, where the saved details and section status are displayed. New optional registration certificates and national ID documents are validated by PHP and stored as `MEDIUMBLOB` data in the member's profile row, avoiding a dependency on writable web-server upload directories. Both document fields accept PDF files only; national ID scans should be a single PDF containing the front and back. Existing legacy file paths remain supported in profile summaries.

The member Profile page includes a membership-card preview and PDF download. Members can preview their card at any time; the download is enabled only after all required Address, Business, Network, and Citizenship profile fields are complete. Cards use the supplied HOU logo and profile placeholder, are generated at standard CR80 card dimensions, and embed locally bundled Poppins fonts (licensed under `client/assets/fonts/OFL.txt`); no additional Composer packages are required.

### Member payments and IOTEC setup

The member Payments & Invoices page shows the member's confirmed contribution total and payment history (five transactions per page). Payment types are voluntary contributions, the fixed UGX 600,000 membership fee, and the fixed UGX 100,000 supervision fee. Fixed fees are revalidated by the server; voluntary contributions must be between UGX 500 and UGX 1,000,000, matching IOTEC's documented collection limits. With `ChargeCustomer`, IOTEC adds its transaction charge to the requested amount (for example, a UGX 500 contribution may appear as UGX 520.83 collected with UGX 20.83 in charges and UGX 500 received). HOU reconciles the net amount received as the contribution, rather than rejecting the provider's gross collection amount. Transactions remain pending until IOTEC reports `Success`; browser redirects never mark a payment as successful. The `member_payments` table is created automatically on the next portal request, or can be created from `database/HOU.sql`.

The integration follows the [IOTEC Pay API specification](https://iotec.io/api-docs/pay). It uses OAuth 2.0 client credentials to request a short-lived token from `https://id.iotec.io/connect/token`, then starts a mobile-money collection at `https://pay.iotec.io/api/collections/collect`. The request uses IOTEC's `MobileMoney` category, UGX currency, wallet UUID, the member's MSISDN, a unique HOU `externalId`, payer/payee notes, and the configured transaction charge category. Ugandan phone numbers are sent in local 10-digit format (for example `0771234567`).

Set these PHP server environment variables:

* `HOU_PUBLIC_BASE_URL` — public HTTPS portal base URL including `/client`, for example `https://hotspotoperators.org/client`.
* `HOU_IOTEC_CLIENT_ID` and `HOU_IOTEC_CLIENT_SECRET` — client credentials emailed by IOTEC when the Pay account is registered. The application exchanges these for a short-lived bearer token for each payment request.
* `HOU_IOTEC_WALLET_ID` — UUID of the collection wallet in the IOTEC Pay portal.
* `HOU_IOTEC_TRANSACTION_CHARGES_CATEGORY` — optional override: `ChargeWallet` deducts fees from HOU's IOTEC wallet; `ChargeCustomer` charges the member. The current HOU choice is `ChargeCustomer`, which is the default when this variable is unset.
* `HOU_IOTEC_WEBHOOK_SECRET` — random secret of at least 32 characters for the callback security header.

In the IOTEC Pay portal, open the collection wallet's callback settings and add `HOU_PUBLIC_BASE_URL/api/payments/callback.php` as a **Collection** callback. Add this security header (the value must match the server's `HOU_IOTEC_WEBHOOK_SECRET`):

```text
X-HOU-Webhook-Secret: <same value as HOU_IOTEC_WEBHOOK_SECRET>
```

IOTEC's callback contains its transaction `id`, HOU `externalId`, amount, currency, and status. HOU checks the callback secret, provider transaction ID, UGX amount, and external reference before updating status. `SentToVendor` remains pending; only `Success` increases the member's contribution total. Store credentials only in the PHP server environment or a protected secret store, never in this repository. For Apache/XAMPP, set environment variables for the Apache service and restart it; for PHP-FPM, set them in the pool configuration and restart PHP-FPM. PHP cURL must be enabled, and the database user must be able to create tables.

## Member portal web app manifest

[`client/manifest.json`](client/manifest.json) provides browser installation and launch details for the HOU member portal. It defines the app name, description, start page, launch scope, standalone display mode, portrait orientation, theme and background colors, language, category, HOU logo icon, and shortcuts for Log In and Sign Up. Browsers use these settings when a user installs or launches the portal as a web app. The manifest is not required for ordinary website visits, registration, or login.
